A Docker environment for running Chromium with **Chrome DevTools Protocol (CDP)** support.

The image is meant to be **driven externally over CDP** — for example by
[BrowserHive](https://github.com/uraitakahito/browserhive). Chromium is launched
with a small, opinionated set of flags chosen to make that driving model
predictable:

- Each worker reuses **one tab** for its entire lifetime.
- Navigating to `about:blank` is expected to **fully tear down** the previous
  document — see [Driving model &amp; dbus](/internals/driving-model/).
- The container has **no desktop environment**, so OS-integration probes
  (keychain, gnome-keyring, …) are deliberately suppressed.

## Two images

| Image | Purpose |
| ----- | ------- |
| **Production** | Headless Chromium, minimal footprint (no Node.js / dev tools). CDP on port `9222` via `socat`. → [Production](/getting-started/production/) |
| **Development** | Full environment with VNC (noVNC), Node.js, and dev tools. → [Development](/getting-started/development/) |

## How it fits together

```
   CDP client (e.g. BrowserHive worker)
            │  connects to :9222
            ▼
   ┌─────────────────────────────┐
   │ chromium-server container   │
   │   socat  :9222 → 127.0.0.1:9223
   │   chromium (one tab, CDP)   │
   └─────────────────────────────┘
```

An external worker owns one persistent tab and drives it over CDP; the container
itself has no UI in production (the development image adds noVNC so you can watch
the tab render in a browser).
