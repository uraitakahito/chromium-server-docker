Chrome DevTools Protocol (CDP) 対応の Chromium を動かす Docker 環境。

このイメージは **CDP 経由で外部から駆動される**ことを前提とする（例: Web ページ捕獲サーバの BrowserHive）。イメージが決めることと、クライアントに任せることは次のとおり:

- tab と BrowserContext をどう使うかは **CDP クライアントが決める**。イメージは何も強制しない — [駆動モデルと dbus](/internals/driving-model/) を参照。
- **Back-Forward Cache（bfcache）は切ってある**。履歴で戻るときも要求が出て、CDP の `Fetch` と `Network` から見える — [Chromium フラグ](/configuration/chromium-flags/) を参照。
- **desktop environment を持たない**ので、credential store は `basic` に固定し、D-Bus はプロセスごとの session bus だけを用意している。system bus への probe は失敗のまま残り、既知のノイズとして stderr に出る。

## イメージ

| ターゲット | 目的 |
| --------- | ---- |
| **Production** | ヘッドレス Chromium・最小構成（Node.js / 開発ツールなし）。CDP は `socat` 経由で `9222` に公開。→ [Production](/getting-started/production/) |

かつてのヘッドフル系イメージ（コンテナ内完結の開発環境と `debug` VNC ターゲット）は
`attic/` 配下に凍結保管した。描画の目視確認は headless worker のまま
`chrome://inspect` のスクリーンキャストで行う。
[worker の動作確認](/getting-started/verify/) を参照。

## 全体の構成

```
   CDP クライアント（例: BrowserHive）
            │  :9222 に接続
            ▼
   ┌─────────────────────────────┐
   │ chromium-server container   │
   │   socat  :9222 → 127.0.0.1:9223
   │   chromium (CDP)            │
   └─────────────────────────────┘
```

外部の CDP クライアントが接続し、CDP で Chromium を駆動する。コンテナ自体に
UI は無い。tab の描画を見たいときは `chrome://inspect` のスクリーンキャストで
worker を開く — headless のまま機能する
（[worker の動作確認](/getting-started/verify/) 参照）。
